exo — Exponential Organizations

A lecture and workshop companion for Salim Ismail's Exponential Organizations: a fully public handout anyone can read with no account, and an invite-only builder that walks a member from an AI interview to a press release from the future, set in a newspaper. Bilingual Hebrew and English, Hebrew first, everything mirrored.

Sprints

Sprint 0 — kickoffdone

Interview, thin intro spec, deep web research on comparable tools, data model approved at the gate, full spec in fourteen chapters, backlog with a verified traceability matrix.

Sprint 1 — foundationdone

The isolated app: its own base template, nav, error pages and stylesheets; the reference models; the idempotent seed; the DRF read API; the bilingual machinery (strings.py + {% t %}, and a middleware that uses translation.override so a language can never leak to the next request).

Sprint 2 — learn, the public handoutdone

The landing, the handout, a page per attribute. No login, and no prompt to log in anywhere in the open half — the single build button on the landing is the one door, asserted by test.

Sprint 3 — accessdone

Request, wait, approve, revoke; Avi's cockpit; and the remote approval key built to the BKM — one job, group named in code, never creates a user, never escalates, fails shut when unset. Twenty-one tests, most of them refusals.

Sprints 4–8 — the journeydone

Concepts and the AI adapter; the interview that settles into an MTP; the brainstorm across thirteen slots; AI options per slot with selection that survives a regenerate; the document, the press release, five newspaper styles, the exponential score and the stress test.

Sprint 9 — visibility and the museumdone

Public forever, public until a time, specific people, or private — with visibility computed as a query, so a timed release expires without any scheduled job to fail quietly at 3am. The museum, likes that cannot double-count, and view counts that ignore a refresh.

Sprint 10 — cockpit, limits, hardeningdone

Moderation that hides without destroying; the usage view reading the same guard the guards enforce; three cost ceilings and a provider timeout; the moderation gate before anything reaches the public wall; the phone pass in both directions.

Decisions worth remembering

Bilingual without gettext. Interface copy is a dict in strings.py read through a {% t %} tag; content is _he/_en field pairs with a fallback to the other language. No locale catalogs, because neither this machine nor Render has msgfmt, and a build that depends on a binary nobody has is a build that breaks on the day it matters. A missing key renders as the key, on purpose.
Stub mode is a feature. With no OPENAI_API_KEY the adapter produces deterministic local content, so the whole journey runs end to end with no key and no bill — the entire test suite uses it. It is labelled in the UI, because content that looks generated and is not would be a lie told by omission.
Visibility is a query, not a job. A timed release stops matching the museum queryset the moment its time passes. Nothing runs on a schedule, so nothing can fail while nobody is watching, and the row is never rewritten.
Moderation fails open. A release going public is screened first; private and specific-people work is never sent anywhere. If the check cannot run, the release publishes and the failure is logged — a moderation outage that silently froze the museum during a live workshop would do more damage than the rare thing it would have caught, and Avi can hide anything from the cockpit in one tap.
