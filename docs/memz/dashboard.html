SPR-Z.9 A joining player's own uploads, in a shared game
DONE (dev) · 2026-09-16

Post-epic, same day: upload quota tightened to 5 free / 50 paid (was 100/2000); own_only/mix now draw from every currently seated signed-in player's own uploads, not just the host's, so a game you join can include your own photos, not only ones you host. At least one dealt image per round comes from someone's stock when available, in every mode including Same Meme, capped session-wide at 30% and checked against real dealt history, not a per-round guess — a player is never dealt their own upload back (best-effort in own_only with a very small pool). A plain-text notice on the upload form now asks people not to upload photos of others, celebrities, or existing memes, rather than a second unreliable detection pass. The real trap: an early version re-checked the 30% cap per player mid-round, which let one self-excluded player's forced public pick poison the cap for the rest of that same round — fixed by deciding once per round, from the state before it started. 7 features, 10 tests, full memz gate (292 tests) green.

SPR-Z.10 The round Avi asked for
DONE (dev) · 2026-09-18

Avi played real games, then described the round he actually wants, end to end — and this is it. Three image swaps: throw back the picture you were dealt, up to 3 times a round, without losing what you already typed (refused in Same Meme mode, where one shared picture is the point). The reveal is now the vote: each meme gets 10 seconds on every screen at once, with three buttons under it — אוהב (2), ככה ככה (1), פחות (0) — and the separate grid where everyone picked one favourite at the end is gone. The author of the meme on screen can't rate it and gets Avi's own line instead: "תעשה פרצוף תמים...". A verdict only counts for the meme actually showing, checked server-side against the same deadline arithmetic the clients run, or one client could have rated the whole round the second it opened. Nobody is ever named: the round result, the podium gallery and the payload behind them no longer carry the author at all — only "שלכם" on your own, visible only to you. Names stay on the leaderboard; the link between a person and a joke is never drawn ("זה ישמור על מבוכה"). Scoring follows: a plain sum of the verdicts, the old winner/unanimous bonuses dropped, and the ranking tiebreak now counts אוהב verdicts rather than rows. The `Vote` table changed shape (one row per voter per meme, with a value), which meant a migration and rewriting the 10 existing tests that drove the game through the old voting phase. 8 features, 14 new tests + 2 new screens in the contract.

ACT-Z.7Three bugs from Avi's own QA pass on the live game: the captioning keyboard dismissing itself every second (and erasing what was typed), all memes revealing at once instead of one at a time (F-Z.3.9's gap, also tracked since SPR-Z.3), and a Hebrew caption rendering backwards when it opens with an English word, digit or emoji. All three found and fixed the same day; one (the reversed text) needed real investigation before the actual trigger was found.
ACT-Z.8A second QA round straight after: the solo creator's live preview turned out to draw nothing at all (a missing HTML attribute crashed its own script before it ever drew a frame), and once fixed, scrambled every Hebrew word's letters a second way — its own hand-rolled reshaper fighting the browser's own native canvas bidi. Also: voting and the round-result screen no longer rebuild their whole DOM on every poll, which was the real source of the "jumpy, keeps refreshing" feeling while choosing the funniest meme.
ACT-Z.9A third QA round: every countdown, and the reveal slideshow's own timing, compared a server deadline against the device's own clock — wrong on any phone whose clock isn't accurate. The state payload now carries the server's own time on every poll so the client can correct for its own clock's offset instead of trusting it outright. The Hebrew-reversal report was raised again and re-verified fixed a third time (this round: Chromium and WebKit both, Safari's engine specifically checked and cleared) — no further bug found; most likely explanation is a meme rendered before either fix landed, which keeps its old frozen image forever.
ACT-Z.10SUPERSEDED — see ACT-Z.11. A real screenshot from the live game proved the Hebrew report right a fourth time — but it didn't reproduce against any locally-installed version of the bidi library. First diagnosed as `requirements.txt` pinning a range, not an exact version, so dev and production had quietly drifted onto different builds; pinned exactly, deployed, confirmed live — and the exact same meme still rendered reversed, disproving the theory.
ACT-Z.11The real fix. Production's Pillow build (Linux wheel) bundles `libraqm`, giving `ImageDraw.text` its own genuine bidi reordering — so production was reordering the already-reordered string a second time, on every multi-word Hebrew caption, not just ones with punctuation (confirmed directly against production: even "רגע מה קורה פה", no punctuation at all, reproduced it). Windows dev wheels don't bundle raqm, which is why nothing ever reproduced locally. `render.py` now checks `PIL.features.check_feature("raqm")` once at import and skips its own reordering when PIL will do it (passing `direction="rtl"` instead) — the same fix shape as ACT-Z.8.2's browser-canvas double-reversal, just server-side. Found by comparing the disputed glyphs against known-correct and known-reversed single-word reference renders side by side, not by reading images directly. Deployed and verified live: a fresh 3-player game, three brand-new captions never tested before, downloaded straight from production after the deploy — all render correctly.
ACT-Z.12Same screenshot, a second real bug: a caption's emoji baked in as a visible broken-glyph box. Heebo Black has zero emoji glyphs (checked directly against its own cmap table) — spec always said emoji should be dropped, nothing ever did it. `render.strip_unsupported_chars` now reads the font's cmap and drops any character it can't draw before wrapping, turning it into a space rather than nothing so two words don't fuse together where an emoji used to sit. Closes §14.4 (the "render or drop" decision, made in SPR-Z.2 but never implemented) — the "drop" half is done; a live preview warning when it happens is not yet built.
ACT-Z.13"הרגע של חשיפה מאד קצר" — the reveal slideshow's per-meme timer raised from 4s to 8s (`REVEAL_SECONDS_PER_MEME`). Both the server's own `reveal_deadline` sizing and the client's slideshow index already read this one config value, so no other code changed.
